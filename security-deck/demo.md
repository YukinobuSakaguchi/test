# 実演台本（約3分）— Googleの強固な保護を見せる

作成日: 2026-10-28
前提: **登録は完了させない**。テスト用アカウント、または画面（スクリーンショット）だけで見せる。実演の操作は発表者が行う。

## 方針

スライド18（「では、実際に見てみましょう」）から実演に入り、終わったらスライド19（今夜やる3つ）へ戻る。スライドは手動めくりなので、実演中は止まったままでよい。

高度な保護機能プログラムは、鍵を失うとアカウントから締め出される恐れがあり、外部アプリ連携も制限される（レポート第6章）。登録には回復手段の追加が必要で、締め出された場合の復旧に数日かかることもある（[24]）。そのため本番アカウントで登録操作はしない。

### 案内ページの読むポイント（公式文言で確認して読み上げる）

レポート第6章 [22][23][24] に基づく項目。画面の実際の文言と違えば、画面を優先する。

1. 新しい端末・ブラウザでのログインにパスキーまたはセキュリティキーを要求する（ログイン済みの端末で毎回求めるという意味ではない）
2. データにアクセスする外部アプリが制限される（「Googleでログイン」が全面禁止になるわけではなく、要求する権限やアプリの確認状況による）。自作スクリプト・古いメールアプリ・業務連携は先に使えるか確認。アプリパスワードは使えない
3. 不審なファイルの追加チェックと、アカウント復旧時の本人確認の強化。本人が締め出されたときの復旧にも手間と時間がかかる
4. 登録時に回復手段（再設定用のメール・電話、または追加のパスキー／セキュリティキー）を用意する
5. 利用は無料。物理キーの購入は必須ではない（現行の公式案内）。ただし重要なアカウントは、普段使う端末とは別に登録した物理キーを持つ構成をレポートは勧めている
6. 組織のGoogle Workspaceは管理者の許可・設定が関係する

### 言い方（断定しない）

- 言う: 「新しい端末では、パスキーかセキュリティキーがないとログインできなくなります」
- 言わない: 「パスワードでのログインが完全に禁止されます」— 公式文言の照合が未了のため、案内ページで確認できた場合に限り、その表現に合わせる
- 言わない: 「これで全部安全」— ログイン済み端末の操作、アカウント外の詐欺、他社サービスの設定は別（レポート第10章）

### 今夜やる3つ（レポート「先に実行するなら」「今日確認する項目」より）

1. 主要メールとGoogle・Appleのアカウントに、パスキーまたは強い二段階認証を設定し、使い回しをやめる
2. スマートフォンの画面ロックを強くし、OS・ブラウザ・アプリを更新する
3. 予備のログイン手段（別の鍵・バックアップコード・回復手段）を、普段のスマートフォンと別の場所に用意する

## うまくいかないとき

- パスキーのログイン画面が出ない: 付録3を表示し、スクリーンショットで説明して先へ進む
- ネットに繋がらない: 同上。案内ページの画面写真を用意しておく
- 会場から「今すぐ登録したい」と聞かれた: 回復手段を先に用意し、別の安全な環境で主・予備の認証手段を確認してから。既存のログイン済み端末を残したまま進める（レポート第6章の手順）
