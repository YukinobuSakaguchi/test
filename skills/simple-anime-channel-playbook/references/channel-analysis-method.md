# 参考チャンネル分析の手順

伸びているチャンネルから「再現できる型」を取り出すための手順書。SKILL.md のモードAで使う。

目次

2. データの集め方

## 1. 目的と原則

目的は「何を・どう作れば・なぜ見られているのか」を、自分の制作にそのまま使える粒度で言語化すること。

- **上位だけを見ない。** 再生数上位だけを見ると、どのチャンネルにも共通する要素まで「勝因」に見えてしまう（生存者バイアス）。上位・最新・下位を並べ、上位にだけあるものを探す。
- **事実と推論を分ける。** 各記述に次のどれかを付ける。
  - 【確認済み】データや画像で確かめたこと。根拠（動画ID、時刻、取得日）を添える。
  - 【推論】観察から推測したこと（制作ツール、狙い、視聴者層など）。推論の根拠も一言添える。
  - 【提案】自分のチャンネルでどう使うか。
- **型は抽象化して書く。** 「〇〇というセリフで始まる」ではなく「冒頭3秒で、主人公が不利な状況にいることを一言で示す」のように、別の題材にも移せる形にする。固有のセリフ・キャラ・絵柄は記録してもよいが、型として採用しない。
- **数値には取得日を付ける。** 再生数・登録者数は変動する。

## 2. データの集め方

### 2-1. スクリプトで集める（YouTubeに接続できる環境）

```bash
pip install "yt-dlp[default]"   # JavaScript 実行環境（Deno または Node.js）も必要
python scripts/collect_channel.py @handle --out analysis/handle --storyboard-videos 3 --comments 30
```

- 動画ファイル本体はダウンロードしない。取得するのは一覧、詳細、字幕、サムネイルと、オプション指定時のストーリーボード（シークバーのプレビュー画像）、上位コメント本文。
- 必要な接続先: `youtube.com`、`*.youtube.com`、`*.ytimg.com`。Claude Code のクラウド環境では、環境設定の Network access で許可ドメインに追加する。
- 出力のうち、最初に読むのは `summary.md`。表計算で見たい場合は `videos_list.csv` / `sample_details.csv`（UTF-8 BOM付きなので Excel でそのまま開ける）を使う。
- 詳細取得で失敗が続く場合（`Sign in to confirm you're not a bot` 等）は `--player-client tv,web_safari` などを試す。それでも失敗するなら、取得できた範囲で分析し、欠けた項目を明記する。

### 2-2. 手動で集める（接続できない環境）

ユーザーに次を依頼する。全部そろわなくても、そろった範囲で分析し、欠けている観点を明記する。

1. チャンネルトップ（登録者数・説明文）と、動画一覧を「人気順」で表示した画面のスクリーンショット
2. 再生数上位5本・最新5本・再生数が少ない3本のURLとタイトル
3. 上記動画の説明文（クレジット欄に制作ツールや素材の出典が書かれていることが多い）
4. 上位2〜3本の字幕テキスト（YouTubeの「文字起こしを表示」からコピー）、または冒頭1分の書き起こし
5. 第5章の観察シート（動きの細部は人が見ないと分からない）

### 2-3. サンプルの選び方

長尺とショートは別々に選ぶ（役割も視聴のされ方も違うため）。

| 区分 | 本数の目安 | 目的 |
|---|---|---|
| 再生数上位 | 8 | 当たりの共通点を探す |
| 最新 | 5 | 現在の作り方（初期と変わっていることが多い） |
| 再生数下位 | 3 | 当たりとの差分を見る対照群 |

## 3. 分析の観点

### A. ポジショニング（何のチャンネルか）

- ジャンル・題材（恋愛、職場、家族、学校、あるある、スカッと系、ホラー、教育など）と、想定視聴者【推論】
- 固定キャラクターやシリーズの有無、1話完結か連続ものか
- 長尺とショートの本数・再生数の比率、それぞれの役割【推論】
- 伸び始めた時期と、そのきっかけになった動画（月別の再生数中央値が跳ねた月と、その月の上位動画）

### B. 何が当たっているか

- 中央値の3倍以上の再生数を「当たり」とし、当たりの共通点をテーマ・タイトル・サムネ・尺の4軸で探す
- 当たりと下位の差分を言語化する（差分がない軸は勝因ではない可能性が高い）
- 当たりが特定のシリーズ・テーマ・フォーマットのどれに依存しているか

### C. タイトル

- 文字数、記号（【】「」！？…）、数字、感情語、疑問形、結末の匂わせ方
- 共通の型を抽象化する（例の書き方: `【ジャンル】＋状況＋結末の予告` のように要素で書く）
- シリーズ名や話数の表記ルール

### D. サムネイル（画像を実際に見る）

- 構図: キャラの人数、顔の大きさ（画面に占める割合）、表情の強さ、視線
- 文字: 文字数、行数、色、縁取り、位置。タイトルと同じ内容か、補完しているか
- 背景・色調、シリーズとしての統一感（一覧で見て同じチャンネルと分かるか）
- 縮小表示（スマホの一覧サイズ）でも文字と表情が読めるか

### E. 動画構成（字幕・ヒートマップ・視聴で確認）

- **冒頭フック**: 最初の5〜30秒で何を提示しているか（結論の先出し、対立、問い、異常な状況、前回の続き）
- **ビート分解**: 導入 → 事件 → 展開 → 山場 → 結末 → 余韻・次回への引き。それぞれの開始時刻を記録し、尺に対する比率を出す
- **発話密度**: 1分あたりの文字数（summary.md の「発話密度」）。自動字幕は誤認識を含むので目安として扱う
- **語りの形式**: キャラ同士の会話劇、ナレーション主体、一人語り、その混合
- **ヒートマップの山**: よく再生された箇所に何があるか（オチ、衝撃の一言、表情の変化など）
- **終わり方**: チャンネル登録の呼びかけ、次の動画への誘導、終了画面
- **場面数**: 1本の中の場面（背景）の数と、切り替えの頻度

### F. アニメーション・演出（ストーリーボード画像・サムネ・視聴で確認）

観察する項目:

- キャラの動き: 口パク（何段階で開閉するか）、目パチ、呼吸や揺れ、腕など部位の動き、画面内の移動
- 1キャラあたりの表情差分・ポーズ差分の数
- カメラ: ズーム、パン、画面の揺れ、カットイン、集中線
- 背景: イラスト、写真の加工、単色・グラデーション。使い回しの程度
- 文字: 全セリフ字幕か、強調テロップのみか、吹き出し、効果文字（擬音）
- 音: 声の種類（人の声、合成音声、一人で複数役）、BGMの切り替え頻度、効果音の多さ

制作方式の見分け方（判定は【推論】。説明文などに明記があれば【確認済み】）:

| 見え方 | 推定される方式 | 代表的なツールの例 |
|---|---|---|
| 体は静止し、表情やポーズが画像ごと切り替わる。口は2〜3段階で開閉 | 立ち絵差分方式 | ゆっくりMovieMaker4、AviUtl、一般的な動画編集ソフト、PowerPoint |
| 顔の向きや体が、描き直しなしで滑らかに変形して動く | 2Dパペット（メッシュ変形） | Live2D、Adobe Character Animator、Cartoon Animator、After Effects |
| 線や形が毎フレーム描き直されている | フレーム作画 | CLIP STUDIO PAINT、Procreate Dreams、OpenToonz、Krita |
| 漫画のコマや吹き出しの上をカメラが移動する | 漫画動画（静止画＋カメラワーク） | 一般的な動画編集ソフト |

最後に「1本あたりに新しく描く必要がある素材」を推定する。ここが量産性（投稿ペース）を決める。

### G. 運用

- 投稿頻度、曜日、時刻（RSS由来の正確な日時を使う）
- 説明文の構成（あらすじ、クレジット、ハッシュタグ、関連動画リンク）
- 再生リスト・シリーズの導線
- コメント欄の反応: 視聴者が何に反応しているか（共感、ツッコミ、続編の要望、キャラへの愛着）

## 4. 進め方

1. `summary.md` を読み、A・B・C・G の当たりを付ける。
2. サンプルのサムネイル画像を実際に開いて D を見る。上位と下位を並べて比べる。
3. 上位3本は字幕を通して読み、E のビート分解を時刻付きで行う。下位2本も同じように分解して比べる。
4. ストーリーボード画像で F の大枠（絵柄、構図、背景、文字の出し方）を見る。動きの細部はストーリーボードでは分からないので、第5章のシートでユーザーに確認してもらうか、「未確認」と明記する。
5. 「当たりの型」を3〜5個にまとめる。各型に根拠（動画IDと時刻）と、下位動画との差分を書く。
6. 自分のチャンネル向けに翻訳する: 参考チャンネルの型を、自分の工数・ツール・キャラクターで実現する方法に置き換える。そのまま写さない。

## 6. この分析でわからないこと

- クリック率、平均視聴時間、視聴者の属性、流入元は、チャンネル所有者の YouTube Studio にしかない。ヒートマップ（よく再生された箇所）は視聴維持率の代わりにはならない。
- 相関は因果ではない。当たり動画の共通点は「勝因の候補」であり、自分のチャンネルで小さく試して確かめるもの。
- 自動字幕は誤認識を含む。固有名詞や話者の区別は不正確。
- 一覧の投稿日は「〇か月前」表示からの概算。正確な日時はサンプル動画とRSS（最新15本）だけ。
